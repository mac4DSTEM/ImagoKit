# Contributing to ImagoKit

Thank you for your interest. Bug reports, questions, documentation fixes and pull requests are welcome.

## Build and test

ImagoKit is a Swift package (Swift 6.2 or newer; macOS 15 or iOS 18 or newer). The FFT engine uses Accelerate, so the
package builds on Apple platforms only for now.

```bash
swift test -c release        # or tools/test.sh, which wraps it
tools/consumer-check/run.sh  # compiles a separate package against the public API only
tools/readme-consumer/run.sh # compiles and runs the README's example
```

Tests use [Swift Testing](https://github.com/swiftlang/swift-testing) (`import Testing`, `@Test`, `#expect`). Run the
tests in release mode (`-c release`); debug builds are much slower on the numerical code.

## Numbers and fixtures

Results are checked against pinned reference output from NumPy, SciPy and scikit-image (versions in
`tools/oracle/references-lock.txt`) and against planted inputs whose answer is known, such as a lattice with a known
spacing. The fixtures are committed under `Tests/*/Fixtures` and generated by the scripts in `tools/`.

If a test disagrees with its fixture, treat it as a bug in the code, not as a tolerance to widen. If you believe a
fixture is wrong, say why in the issue or pull request. A change that moves a pinned number should update the fixture in
its own commit, with the reason in the message and in `CHANGELOG.md`.

## Pull requests

- Keep each pull request focused, with tests that fail before the change and pass after it.
- Public API is `public`; do not expose anything an application would need as `package`.
- Update the documentation and `CHANGELOG.md` when behaviour changes.

## Reporting issues

Please use the issue templates. For a wrong number, include the input (or a small script that makes it), the result you
got, and the result you expected from the reference package. For security problems, see [`SECURITY.md`](SECURITY.md).
