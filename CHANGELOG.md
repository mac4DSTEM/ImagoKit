# Changelog

ImagoKit follows semantic versioning; before 1.0.0 a minor version may break the API, and its Migration paragraph says how.
Every number is held by regression tests against NumPy 2.5.4, SciPy 1.18.1 and scikit-image 0.26.0 (the pins in
`Tests/*/Fixtures`, regenerated by `tools/slice-*/pins.py`) and by planted inputs whose answer is known.

## 0.4.0 (2026-10-21)

Spline-order line profiles and the capped thumbnail; everything is additive.

### Added
- `LineProfile` at spline orders 2 to 5 (`ProfileOrder.quadratic` … `.quintic`): SciPy's B-spline prefilter (`ni_splines.c` poles
  and gain, mirror/reflect/wrap initialisation, the 12-pixel pre-pad for `constant`/`nearest`) and tap sums, all five modes.
  Pinned against 1080 `skimage.measure.profile_line` cases (`tools/measure/spline_pins.py`): `.float64` within 1e-13 of the
  image maximum (measured 3.9e-15), `.float32` within 2e-6 (measured 4.7e-7). Cost: one pass over the image per call.
- `Thumbnail.init?(width:height:normalized:maxSide:)`: the initialiser that enforces a cap (macTEM's 96 = `defaultMaxSide`).
- The app's bilinear fold needs no new option: `LineProfile.sample(order: .linear, mode: .reflect, reduce: .mean,
  arithmetic: .float64)` is it (pinned in `float64PathIsTheConsumersNamedVariant`, gap 4e-15). The app wraps the two refusals
  (width below 1, a degenerate segment) itself.

### Migration
None required. macTEM deletes its `Thumbnail` size check and its `LineProfile` copy (the named variant above); the `ScaleBar`/`LengthUnit` renames are the app's own.

## 0.3.0 (2026-10-20)

0.2.0 is released; everything below is additive.

### Added
- `ImagoCore.Colormap` (`viridis`, `inferno`, `gray`, `rdbu`): the 256-entry RGBA tables and `color(at:)`, with
  `DisplayMapping.init(low:high:gamma:colormap:)` and `DisplayMapping.sampleRGB(_:_:)` (the linearly filtered table lookup).
  The tables are the display's anchor maps, NOT matplotlib's (matplotlib is not in the pinned environment); pinned byte for byte
  to a NumPy reading of the anchors, itself equal to the application's table bytes (4 maps, 4 sizes; 2001 sampler points).
- `ImagoCore.Segmentation`: `label` (mask or value map, 4- or 8-connectivity) equal to `skimage.measure.label` exactly, and
  `objectMoments` (area, bounding box, centroid, covariance, inertia eigenvalues, axis lengths, scikit-image `orientation`)
  to 1e-12 (relative above 1, absolute below) of `regionprops`, plus the extents along and across the principal axis, the image-frame direction and
  the edge flag, pinned to an application's Float32 routine (2e-5 relative).
- `ImagoFFT.RadialChartScale.samples`, `drawable`, `nearest`, `powerAxisMarks`, `FFTMask` (defaults and ranges), a failable
  `RadialProfile.init(width:units:mean:count:)` and a public memberwise `SpotMeasurement.init`.
- `ImagoCore.CSVText` (`number` as `%.17g`, `headerValue`, `quoted`, `scaleLine`), `TidyResultsCSV`, and in ImagoFFT
  `FFTExportHeader`, `FFTExportText`, `RadialProfileCSV`, `SpotsCSV`: pure text functions pinned byte for byte against an
  application's own writers on 46 seeded cases. The caller supplies the first-line title, the validation and lineage
  sentences, and (tidy file) the description lines; the kit authors no claim. One header line keeps the application's wording ("the app's conversion").
- Pin generators: `tools/colormap`, `tools/segmentation`, `tools/radialchart`, `tools/csvexport` (the application-reference
  ones need a scratch binary built from the application's source; each docstring says how).

### Migration
None required: nothing existing changed. A consumer that switches its own tables, labelling, chart preparation and CSV writers
to these deletes them. Not in the kit: the line-profile CSV, the PNG export provenance, and every UI type.

## 0.2.0 (2026-10-16)

The calibration units, measurement, histogram, line profile and display numerics.

### Added
- `AxisCalibration.offset` and `AxisCalibration(offset:scale:unit:)`: the axis written as the physical value at pixel 0
  (`origin = -offset / scale`), as image formats and RosettaSciIO write it.
- `LengthUnit` conversions: `angstromsPerPixel(scale:unit:)`, `reciprocalAngstromsPerPixel(scale:unit:wavelengthAngstrom:)`
  (Å⁻¹, nm⁻¹, mrad), `canonicalRealUnit`, `canonicalReciprocalUnit`, `isPhysicalReciprocal`, `isPixel`,
  `editableRealUnits`, `editableReciprocalUnits`, and `normalized(_: String?)`. Tests pin every spelling and scale
  against a transcription of an application's unit table and check the closed forms. `LengthUnit.nanometres(per:)` is the one
  nanometre table (an application's own duplicate can be deleted); the Å conversion deliberately reads only Å, nm, pm.

- `ImageMeasurement` (`PixelPoint`, `distance`, `angle`): distance in pixels and, with both axes calibrated in one unit,
  in that unit using each axis's own scale; the angle at a vertex by `atan2(|cross|, dot)` with Kahan's cross product, in
  the physical plane when it is defined. Pinned to random triples from NumPy float64 (4e-16 and 1e-13 relative) and to
  planted angles.
- `IntensityHistogram.histogram(_:bins:range:)`: `numpy.histogram` of the finite pixels of a Float32 array with NumPy's
  float32 edge and index arithmetic, bit for bit (40 pinned cases: constants, signed zeros, planted edge values, a denormal
  range, explicit ranges) and NumPy's errors as `HistogramError`. `compute(_:bins:range:)` is the variant that keeps the
  statistics when NumPy raises "Too many bins for data range" (empty counts and edges).
- `LineProfile.sample(...)` and `unreduced(...)`: `skimage.measure.profile_line` for orders 0 and 1, the five modes
  (`constant`, `nearest`, `reflect`, `mirror`, `wrap`), `linewidth`, `cval` and `reduce_func` (mean, sum, min, max, median or
  a closure). `.float32` arithmetic is scikit-image on a float32 image and matches it bit for bit on 368 pinned profiles
  (9244 samples, including NumPy's pairwise float32 sum); `.float64` matches scikit-image on the widened image to 8.9e-16 of
  the image maximum. Orders 2 to 5 and multichannel images are absent.

- Display numerics (Float32 or Double, no UI, no colormap, no text metrics), pinned by `tools/display/pins.py`, an independent
  NumPy / Python reading of each definition (no package implements these; bit for bit unless stated):
  - `ImagoCore.DisplayNormalization`: `finiteMinMax`, linear and zero-centred `normalized` with non-finite pixels at
    `invalidValue` (-1), `logContrast` (log₁₀(1 + max(p, 0))), `normalizedLog`.
  - `ImagoCore.Thumbnail.make`: the box-average downsample (floor boxes by integer division, invalid pixels left out,
    never upscaled).
  - `ImagoCore.ScaleBarMath`: `overlayScale`, `sampling` (a metre axis shown in nm, µm or mm), `nice125`, `ladder`, `format`
    and `plan` (the label, the unrounded and drawn length). The plate's fit stays with the caller, as does the spelling
    of a unit (`unitLabel`).
  - `ImagoCore.DisplayMapping`: window, gamma and a 256-entry colour table to 8-bit RGB in Double (the exact reference for a
    shader's Float32 arithmetic), masked grey for negative values.
  - `ImagoFFT.FFTRegion` (the square even region: drawn, moved, resized, typed, centred, valid), `SpectrumBin`,
    `RadialChartScale.decadeMarks`, `SpectrumShape.aspect` and `FFTUnits` (length, reciprocal and spectrum units shown in nm
    and nm⁻¹), on `LengthUnit.nanometres(per:)`.
  - `ImagoFFT.SpectrumDisplay`: v = log₁₀(|F|² / (W·H)²) per bin (NaN for the DC and for zero or non-finite power) and the
    default window (median by a 2048-bin histogram, white beyond 3 bins of the centre); the log matches NumPy's to the last
    bit of Float32 on the pinned cases.

### Migration
None: every addition is new API; existing 0.1.0 call sites compile unchanged. `AxisCalibration.init(scale:unit:origin:)` is unchanged; `offset` and `init(offset:scale:unit:)` are added beside it.

## 0.1.1 (2026-10-16)

### Added
- `ImagoFFT.FFT1D` (Float) and `FFT1DDouble` (Double): public, Sendable radix-2 complex transforms,
  `init?(n:)`, `n`, `transform(re:im:forward:)` and `nextPow2(_:)`. Both directions are unnormalised;
  divide inverse output by `n` to match NumPy's default inverse. Length one is the identity;
  nonpositive and non-power-of-two lengths are refused.
- NumPy 2.5.4 complex128 fixtures for lengths 1, 2, 4, 8, 64, 256 and 1024, generated by
  `tools/fft1d/pins.py`. Tests use complex-bin error ≤ tolerance × max(1, |oracle|):
  1e-5 for Float and 1e-12 for Double, plus round-trip scaling and shared-plan concurrency checks.

### Changed
- Relicensed the entire package to GPL-3.0 by the copyright holder (2026).

### Migration
The FFT APIs are additive. Existing APIs are unchanged. Distribution must comply with GPL-3.0; see `LICENSE`.

## 0.1.0 (2026-10-15)

### Added
- `ImagoAlignment`, drift and stack alignment, on the Float32 and Float64 paths:
  - `PhaseCorrelation.register(reference:moving:upsampleFactor:normalization:precision:)`, scikit-image's
    `phase_cross_correlation` (no masks, no `disambiguate`): the shift to apply to the moving image, the error and the phase
    difference (`ImageRegistration`, `PixelShift`, `Normalization`).
  - `ImageShift.shift(_:by:order:mode:cval:precision:)`, SciPy's `ndimage.shift` with orders 0 and 1 and the modes
    `constant`, `nearest`, `wrap`, `reflect`, `mirror`, `grid-constant`, `grid-wrap` (`ShiftOrder`, `ShiftMode`);
    `ImageShift.fourierShift` and `fourierShiftWithResidual`, SciPy's `ndimage.fourier_shift` on the image's FFT.
  - `DriftSeries.estimate(_:reference:upsampleFactor:normalization:precision:)` against the first frame, the mean frame or the
    previous frame (cumulated) (`DriftReference`).
  - `AlignedSum.sum(_:shifts:method:precision:)`: the aligned sum and mean with the per-pixel overlap count
    (`AlignmentMethod`, `AlignedStack`).
  - `AlignmentError` with texts.
- DocC catalogues for `ImagoCore`, `ImagoFFT` and `ImagoFilters`; a README whose program is compiled and run by
  `tools/readme-consumer` in CI.

### Changed
- Nothing in 0.0.2's API.

### Fixed (before release)
- `ImageShift.shift` in `reflect` mode returned `cval` for a whole-number shift of 4n, 6n, … pixels on an axis of n pixels
  (a coordinate reduced to exactly 0 by the period was mapped outside); now the reflected pixel, as SciPy. Tested by the
  periodic-mode identity (a shift by whole periods returns the image) for `reflect`, `mirror` and `grid-wrap`.

### Removed
- `ImagoAlignmentScope`, the placeholder that named the module's registration.

### Known limits
- The shift and its error are compared with scikit-image on 330 cases: equal on every Float64 case; on Float32, a case
  whose two largest correlation samples lie within the Float32 noise of the correlation is held to the set of shifts that
  noise cannot tell apart (117 cases), not to equality.
- A first call of a vDSP 1D FFT or DFT size in a process can differ from later calls by one Float32 ulp (up to 7.9e-8 of the
  maximum, intermittent; also in the code ImagoCore's `FFT2D` came from). No result is promised bit-identical between two
  runs of a Float32 product.

- `DriftSeries.estimate` holds every frame's spectrum at once (a 20-frame 4096² stack needs about 2.7 GB on Float32, 5.4 GB
  on Float64); `.mean` gives shifts relative to the stack's average position, accurate to about 0.2 px on a drifting stack
  (scikit-image's own error there); the Float32 path returns shifts as `Double(Float)` (5.1 reads 5.0999999).

### Migration
Additive: no 0.0.2 code changes. Depend on the product `ImagoAlignment` to use the new module. Code that named
`ImagoAlignmentScope` deletes that line.

## 0.0.2 (2026-10-15)

### Added
- `ImagoFFT.MaskedInverseFFT` (Bragg filtering: raised-cosine spots with their Friedel partners, the union by maximum,
  `imaginaryMax` reported) and `SpotMeasurement.maskSpot(radius:edge:)`.
- `ImagoFilters.HRTEMFilter`: the average background subtraction and Wiener filters (Kilaas 1998, as D. R. G. Mitchell's
  DigitalMicrograph script describes them), every stage in the result; never compared with DigitalMicrograph.

### Migration
Additive. `ImagoFiltersScope` (0.0.1's placeholder) is gone. For an application that carried the originals of these types, the
switch deletes them and converts its image type to `Micrograph`: `MaskedInverseFFT.compute` takes a `Micrograph` and
returns `SpectrumValues`; `HRTEMFilter.filter` returns a `Result` and `HRTEMFilter.outputs(_:like:)` gives the two images;
`FFTMask.spot`-style helpers become `SpotMeasurement.maskSpot`; error enums are `MaskedInverseFFTError` and
`HRTEMFilterError` (with `maskCount` for a wrong mask length). The Float32 path is the originals' arithmetic: the same
bits in steady state.

## 0.0.1 (2026-10-15)

### Added
- `ImagoCore`: `Micrograph`, `AxisCalibration`, `PixelCrop`, `LengthUnit`, `Precision`, `FFT2D` (the exact N-point 2D DFT
  for every size on vDSP, Float32) and `FFT2DDouble` (the same algorithm in Double), `FFT2DTransform`.
- `ImagoFFT`: `PowerSpectrum` (`fftshift(fft2(x))` with `fftshift(fftfreq(n, d))` axes), `SpectrumValues`, `RadialProfile`
  against physical |q|, `SpotMeasurement` (snap, Hann window, 5 × 5 centroid, d = 1/|q|, refusals, the neighbour flag), the
  angle between two spots and `LatticePair`.

### Migration
First release. For an application with its own copies of these computations: the image becomes a `Micrograph`
(`AxisCalibration(scale:unit:origin:)` per axis); arrays come as `SpectrumValues`; `RadialProfile.compute` throws instead of
returning nil; a spot is measured with `clickColumn:`; the reciprocal unit of an axis already in "1/nm" is "nm".
