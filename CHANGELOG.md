# Changelog

ImagoKit follows semantic versioning; before 1.0.0 a minor version may break the API, and its Migration paragraph says how.
Every number is held by regression tests against NumPy 2.5.4, SciPy 1.18.1 and scikit-image 0.26.0 (the pins in
`Tests/*/Fixtures`, regenerated by the `pins.py` scripts under `tools/`) and by planted inputs whose answer is known.
Entries from 0.8.1 on are written by release-please from the merged pull requests' titles. A moved fixture is listed under
"Fixtures and tests" (a `test:` title, or one `test:` line per fixture in the pull request's commit override).

## [0.8.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.7.0...0.8.0) (2026-10-22)

The segmentation, restoration and strain release : distance transform, watershed and rolling ball; zoom and rotate; TV and non-local-means denoising; the real-input transform and a mixed-radix Float64 plan; GPA strain. Pinned against NumPy 2.5.4, SciPy 1.18.1 and scikit-image 0.26.0 (`tools/segmentation-k1`, `tools/resampling`, `tools/denoise`, `tools/fft-real`) and planted truth (`tools/gpa`); `docs/parity.md` goes from 87 to 93 rows (36 present).

### Added
- **Real-input 2D transform**: `FFTSurface.rfft2`/`irfft2` (Float64 and Float32) now run on a real-to-complex path (two real rows share one complex
  row transform, then the `columns/2 + 1` columns as complex lines; the inverse backwards) instead of truncating the complex transform:
  512x512 Float64 `rfft2` 2.07 -> 0.72 ms (NumPy 0.65), `irfft2` 4.34 -> 0.63 ms. Same `s=`, `norm=`, axes behaviour; pinned at 16 more shapes
  (`tools/fft-real/pins.py`).
- **1D `rfft` / `irfft`** on `FFT1D` and `FFT1DDouble` (`rfft(_:norm:)`, `irfft(re:im:norm:)` on a plan; static `rfft(_:n:norm:)`,
  `irfft(re:im:n:norm:)` that build the plan and return nil for an `n` that is not a power of two): `n=` truncation and zero padding,
  `norm=` backward/forward/ortho, the imaginary parts of bin 0 and of the Nyquist bin ignored, as `numpy.fft`.
- **Mixed-radix Float64 plan** (`MixedRadixPlanD`, internal): lengths of prime factors 2, 3, 5, 7 that no vDSP plan serves (500, 504, 360, 7, 14, 49 ...)
  no longer take Bluestein: `fft2` Float64 500x500 4.64 -> 1.46 ms (NumPy 1.49), 504x504 4.51 -> 1.26, 360x360 3.03 -> 0.60. The `vDSP_DFT_zop`
  path for 2^n x {1,3,5,15} and Bluestein for every other length stay.
- **Denoising** (`Denoise`, ImagoFilters; `tools/denoise/pins.py`): `totalVariationChambolle`, `totalVariationBregman` and `nonLocalMeans` for a 2D single-channel image, Float32 and Float64, with scikit-image 0.26.0's names and defaults. 536 pinned cases: Chambolle and non-local means (both modes) bit-identical to the compiled package, Bregman within 1e-14 (Float64) and 2.7e-6 (Float32) relative. Refuses a size mismatch, NaN or infinite samples, non-positive parameters and, for Bregman, an axis of length 1 (`DenoiseError`).
- **GPA strain** (`GeometricPhaseAnalysis`, ImagoFilters): geometric phase analysis after Hytch, Snoeck and Kilaas (1998) from two reflections: Bragg-filtered phases, unwrapping-free phase gradients, the distortion tensor D, strain (e_rr, e_cc, e_rc), rotation, amplitudes, an optional reference window, and `findReflections` (the two strongest non-collinear reflections, refined). Rows and columns; Float64 on `FFTSurface`. Planted truth only (`tools/gpa/planted.py`): errors 4.9e-4 (uniform), 1.6e-3 (bump), 1.5e-3 (oblique), 2.5e-11 (perfect) inside 2x the plain-numpy GPA's. **`validation: "none"`** until one dataset with truth passes.
- **Zoom and rotate** (`tools/resampling/pins.py`): `ImageResampling.zoom` and `rotate` (SciPy `ndimage.zoom` and `ndimage.rotate`, 2D, orders 0 to 5, the modes of `ImageShift` and SciPy's default `constant`, `grid_mode`, `reshape`), on the spline machinery of the spline shifts; 476 cases pinned at decimal 6 (float32 1.5e-6). `ImageShift.axisSample` and `combine` are now package-visible helpers; `AlignmentError.invalidResampling` is new.
- **Distance transform, watershed, rolling ball** (`tools/segmentation-k1/pins.py`): `DistanceTransform.euclidean` (SciPy
  `distance_transform_edt`, 2D, `sampling`), `Segmentation.watershed` and `Segmentation.markers` (scikit-image `segmentation.watershed`
  from a marker image or peak coordinates, `mask`, connectivity 4 and 8; labels exact on 23 pinned cases, 12 of them tie-heavy), and
  `RollingBall.background`, `ballKernel`, `ellipsoidKernel` (`restoration.rolling_ball`, Float64 and Float32).
- `ObjectStatistics.feretSummary`: the counts and the median and mean of the counted objects' Feret lengths (`sizeSummary`'s rule on
  `feret_diameter_max`), which mac4DSTEM computed in app code before.
- `MorphologyError.noBackground` (a distance transform of an image with no background pixel is refused: SciPy returns distances to a
  point outside the image); `RestorationError`.

### Changed
- `butterworth` (Float32 and Float64), `PhaseCorrelation.register` and the drift series and the masked correlation transform their real images with the
  real-input transform: 512x512 `butterworth` Float64 6.28 -> 1.45 ms (scikit-image 1.61), Float32 2.61 -> 1.02; `phase_cross_correlation` Float64 7.66 -> 3.14,
  Float32 2.65 -> 2.15; masked 256x256 Float64 62.0 -> 13.1, Float32 28.3 -> 9.7. Values agree to rounding (the pins pass unchanged).
- `FFTSurface` keeps its last six plans (a loop of same-size calls pays the setup once).
- The masked correlation transforms at the next length of prime factors 2, 3, 5, 7 and slices back to `M + R - 1`, as scikit-image does with
  `scipy.fft.next_fast_len` (before: the exact length, Bluestein for 127, 255, 511 ...). Same correlation up to rounding.
- `ImageRegistration.phaseDifference` at upsample 1 is now `atan2(0, peak)`: 0 for a positive peak, pi for a negative one (before: the sign
  of 1e-16 rounding noise in the imaginary part of the correlation); the refined (upsample > 1) value is unchanged.
- The axis-wise 2D path (lengths no radix-2 2D call serves) transposes instead of gathering columns: Float64 480x480 2.03 -> 1.53 ms.

**Migration.** None for a consumer that calls the kit: no signature changed. A consumer that switches over `MorphologyError`, `AlignmentError` or `RestorationError` exhaustively adds the new cases (`noBackground`, `invalidResampling`). The masked correlation and `phaseDifference` values move at rounding level (see Changed). The Float64 `fft2` of lengths 500, 504, 360 and the like is about 3x faster; `butterworth`, `PhaseCorrelation` and masked registration are 2x to 5x faster.

## [0.7.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.6.1...0.7.0) (2026-10-22)

The precipitation release: thresholds, binary morphology, labelled statistics and the rest of `regionprops`, the areal number density
of an object set, and helpers the apps computed in their own code before. Pinned against scikit-image 0.26.0 and SciPy 1.18.1 on planted
inputs (`tools/precipitation/pins.py`); `docs/parity.md` goes from 77 to 87 rows (27 present).

### Added
- **Thresholds** (`Thresholding`, ImagoFilters): `otsu`, `li`, `yen`, `triangle`, `mean`, `isodata` (and `isodataAll`),
  `local` (Gaussian and mean surfaces), `hysteresis`, on Float64, Float32 and integer images (`ThresholdPixels`), computed in the
  image's own dtype with NumPy's uniform-bin histogram; integer images return exact integer thresholds. Plus `mask` (strict compare,
  bright or dark, non-finite is false) and `level(atFraction:)`.
- **Binary morphology** (`BinaryMorphology`, `StructuringElement`, ImagoCore): `erosion`, `dilation`, `opening`, `closing`, `fillHoles`
  (SciPy semantics: odd structures, `iterations` including until-stable, `borderValue`), `generateStructure(rank:connectivity:)`, the
  scikit-image 0.26 `binary_*` defaults (`skimageErosion` etc. with `MorphologyMode`), `removeSmallObjects`, `removeSmallHoles`
  (`maxSize`) and `clearBorder`. Every mask is exact against the pins.
- **Labelled statistics** (`ObjectStatistics`, ImagoCore): `measure(image:labels:)` (sum, mean, standard deviation, minimum and
  maximum with positions, centre of mass) and `findObjects`, over a `LabelImage` and any same-sized image.
- **`Segmentation.regionProperties(_:intensity:)` and `Segmentation.eulerNumber`**: `perimeter`, `perimeter_crofton`, `eccentricity`,
  `solidity`, `equivalent_diameter_area`, `extent`, `euler_number`, `area_filled`, `area_convex`, `feret_diameter_max` (the needle
  length; `axisMajorLength` stays 4√λ1), `intensity_*` and `centroid_weighted`; `RegionProperties.tidyRows` writes the
  `regionprops_table` through `TidyResultsCSV`.
- **Areal density** (`ObjectStatistics.arealDensity`, `edgeWeight`, `numberDensity`, `ArealDensity`): the Miles–Lantuéjoul
  edge-corrected areal density, the length and width summaries, and `N_V = N_A / t` with σ in quadrature; `validation` is "none"; no
  calibration, no density. Moved from mac4DSTEM's `PrecipitateStatistics.density` with the same arithmetic order.
- **Helpers from the apps**: `WindowFunction.apply` (the window product), `ObjectStatistics.sizeSummary` (a particle report's
  counts and median and mean lengths), `PeakLocalMax.find(symmetry:)` with `SpectrumSymmetry` (centre exclusion and one of each mirror
  pair; a kit extension, equal to macTEM's `FFTSpotFinder` pruning on 25 random spectra).
- Errors: `ThresholdError`, `MorphologyError`, `ArealDensityError`.

### Changed
- Nothing existing: every 0.6.1 signature is unchanged (`PeakLocalMax.find` gained a defaulted `symmetry:` parameter).

### Migration
None required to build against 0.7.0. The apps drop their own copies when they move to 0.7.0: macTEM replaces `FFTPreprocess`'s window product with
`WindowFunction.apply`, `ParticleCompute.mask`, `.range` and the threshold value with `Thresholding.mask` / `level` (and offers Otsu through
`Thresholding.otsu`), `ParticleCompute.summary` with `ObjectStatistics.sizeSummary`, and `FFTSpotFinder.find`'s pruning with
`PeakLocalMax.find(symmetry:)`; mac4DSTEM replaces `PrecipitateStatistics.density` with `ObjectStatistics.arealDensity(labels:accepted:analysedPixels:pixelSize:)`.
The one number that can move there is the length and width summary: the app's object lengths are Float, the kit's `ObjectMoments.lengthPx`
and `widthPx` are Double (the areal density itself uses integer counts and boxes, so it is bit for bit the app's).

## [0.6.1](https://github.com/mac4DSTEM/ImagoKit/compare/0.6.0...0.6.1) (2026-10-21)

Pins and documentation; one behaviour change in `PeakLocalMax.find`.

- `PeakLocalMax.find` accepts infinite pixels and matches scikit-image 0.26.0 on them (7 pinned images, float32 and float64, `tools/peaks/inf_pins.py`); 0.6.0 refused every
  non-finite pixel. A NaN pixel is still refused, now as `FilterError.parameter("NaN pixel")`: scikit-image's answer on NaN follows its comparisons with NaN and depends on the
  threshold (it returns no peak when the threshold is the image minimum), and no study input holds NaN. Registered deviation in `docs/parity.md`.
- The spline-shift pins (`splineShiftMatchesSciPy`, 500 cases) are held to SciPy's decimal 6 (1.5e-6), in Float32 and Float64; they were 1e-5 of the image maximum, looser than
  SciPy's own test. The masked-registration pins keep `assert_allclose` defaults for Float64 and 1e-4 for Float32 (the FFT length differs from SciPy's fast length), as the test file says.
- Added `docs/status.md`.

### Migration
None required. Code that caught the 0.6.0 refusal of an infinite pixel now gets peaks; a NaN input is still an error (the message text changed).

## [0.6.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.5.0...0.6.0) (2026-10-21)

The audit release: the FFT surface the FFT room needs, the HRTEM-path filters, spline-order shifts, masked registration and
`peak_local_max`, each pinned against NumPy 2.5.4, SciPy 1.18.1 and scikit-image 0.26.0; `docs/parity.md` is rewritten as a
77-row coverage table and `docs/benchmarks.md` holds the first timings.

### Added
- `FFTSurface` (ImagoCore): `fft2`/`ifft2` with `axes:` (`FFTAxes`) and `norm:` (`FFTNorm`), `rfft2`/`irfft2`, `fftshift`/`ifftshift`
  over `ComplexImage<Float|Double>`; the protocol `FFTSurfaceScalar` for code written over the precision.
- `SeparableFilters.gaussianFilter` and `.uniformFilter` (ImagoFilters), `BoundaryMode`; `BandpassFilters.differenceOfGaussians` and
  `.butterworth`; `WindowFunction.window1D` / `.window2D` (11 families); `PeakLocalMax.find`.
- `ShiftOrder.quadratic ... .quintic`: `ImageShift.shift` at spline orders 2 to 5 (modes `gridConstant`, `nearest`, `reflect`,
  `mirror`, `gridWrap`).
- `PhaseCorrelation.registerMasked` and `.maskedCorrelation` (masked `phase_cross_correlation`, Padfield).
- `SpotMeasurementError.noPower` and `.nonFinite`; `AlignmentError.splineMode`, `.maskCount`, `.emptyMask`, `.overlapRatio`; `FilterError`.
- `Tests/ImagoBenchmarks` and `tools/benchmarks` (timings; off unless `IMAGO_BENCH=1`).

### Changed
- `SpotMeasurement.measure` refuses a constant image or crop (`.noPower`), a window with no power about the snapped bin (`.noPower`)
  and a NaN or infinite pixel (`.nonFinite`); it used to answer NaN (a consumer's ask).
- Spline shifts and `LineProfile` splines share one tap builder; no number changed.

### Migration
`ShiftOrder`, `AlignmentError` and `SpotMeasurementError` gained cases: a consumer's exhaustive `switch` over either needs the new cases (or a `default`);
`ShiftOrder.allCases` now has six members. A caller of `SpotMeasurement.measure` that handled NaN `d` for a flat window now
catches `SpotMeasurementError.noPower` (show "no spot" instead of NaN). Nothing else changes for existing calls.

## [0.5.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.4.0...0.5.0) (2026-10-21)

The Double FFT speed fix and the profile CSV writer, so the apps can delete their copies.

### Added
- `ProfileCSV.text(_:title:appName:start:end:source:validation:method:lineage:shown:)` (ImagoCore): a `LineProfile` as CSV text,
  the lines and order of macTEM's former `ProfileCSV` (header, `position (<unit>),value`, `%.17g` rows, `nan`, the `shown`
  line, the unvalidated clause), tested byte for byte. The caller supplies the title, the validation, method and lineage
  sentences and writes the file. Also `ProfileCSV.method(width:)` and `.noLineage`.
- `LineProfile.init(samples:positions:unit:isPhysical:width:)` is public.

### Changed
- `FFT2DDouble`, its Bluestein transform and `FFT1DDouble` run on `vDSP_DFT_zop` instead of the radix-2 Double calls
  (`vDSP_fft_zipD`, `vDSP_fft2d_zipD`), which are 5 to 7 times slower from 128² up. Release build, one forward 2D transform:
  128² 309 → 61 µs (5.1x), 256² 2.39 → 0.36 ms (6.7x), 512² 13.6 → 2.1 ms (6.5x), 64² 20 → 13 µs. Relative difference to the
  radix-2 path at most 5.7e-16 (machine precision); round trips unchanged at 1e-15. Lengths vDSP has no DFT plan for keep the
  radix-2 call. No API change.

### Migration
None required. macTEM deletes `ProfileCSV.swift` for the kit's writer (and `ExportFile.write` stays the app's). CuboKit's own
FFT is a separate copy and is not affected.

None required. macTEM deletes its `Thumbnail` size check and its `LineProfile` copy (the named variant above); the `ScaleBar`/`LengthUnit` renames are the app's own.

## [0.2.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.1.1...0.2.0) (2026-10-16)

The calibration units, measurement, histogram, line profile and display numerics.

### Added
- `AxisCalibration.offset` and `AxisCalibration(offset:scale:unit:)`: the axis written as the physical value at pixel 0
  (`origin = -offset / scale`), as image formats and RosettaSciIO write it.
- `LengthUnit` conversions: `angstromsPerPixel(scale:unit:)`, `reciprocalAngstromsPerPixel(scale:unit:wavelengthAngstrom:)`
  (Å⁻¹, nm⁻¹, mrad), `canonicalRealUnit`, `canonicalReciprocalUnit`, `isPhysicalReciprocal`, `isPixel`,
  `editableRealUnits`, `editableReciprocalUnits`, and `normalized(_: String?)`. Tests pin every spelling and scale
  against a transcription of an application's unit table and check the closed forms. `LengthUnit.nanometres(per:)` is the one
  nanometre table (an application's own duplicate can be deleted); the Å conversion deliberately reads only Å, nm, pm.

- `ImageMeasurement` (`PixelPoint`, `distance`, `angle`): distance in pixels and, with both axes calibrated in one unit,
  in that unit using each axis's own scale; the angle at a vertex by `atan2(|cross|, dot)` with Kahan's cross product, in
  the physical plane when it is defined. Pinned to random triples from NumPy float64 (4e-16 and 1e-13 relative) and to
  planted angles.
- `IntensityHistogram.histogram(_:bins:range:)`: `numpy.histogram` of the finite pixels of a Float32 array with NumPy's
  float32 edge and index arithmetic, bit for bit (40 pinned cases: constants, signed zeros, planted edge values, a denormal
  range, explicit ranges) and NumPy's errors as `HistogramError`. `compute(_:bins:range:)` is the variant that keeps the
  statistics when NumPy raises "Too many bins for data range" (empty counts and edges).
- `LineProfile.sample(...)` and `unreduced(...)`: `skimage.measure.profile_line` for orders 0 and 1, the five modes
  (`constant`, `nearest`, `reflect`, `mirror`, `wrap`), `linewidth`, `cval` and `reduce_func` (mean, sum, min, max, median or
  a closure). `.float32` arithmetic is scikit-image on a float32 image and matches it bit for bit on 368 pinned profiles
  (9244 samples, including NumPy's pairwise float32 sum); `.float64` matches scikit-image on the widened image to 8.9e-16 of
  the image maximum. Orders 2 to 5 and multichannel images are absent.

- Display numerics (Float32 or Double, no UI, no colormap, no text metrics), pinned by `tools/display/pins.py`, an independent
  NumPy / Python reading of each definition (no package implements these; bit for bit unless stated):
  - `ImagoCore.DisplayNormalization`: `finiteMinMax`, linear and zero-centred `normalized` with non-finite pixels at
    `invalidValue` (-1), `logContrast` (log₁₀(1 + max(p, 0))), `normalizedLog`.
  - `ImagoCore.Thumbnail.make`: the box-average downsample (floor boxes by integer division, invalid pixels left out,
    never upscaled).
  - `ImagoCore.ScaleBarMath`: `overlayScale`, `sampling` (a metre axis shown in nm, µm or mm), `nice125`, `ladder`, `format`
    and `plan` (the label, the unrounded and drawn length). The plate's fit stays with the caller, as does the spelling
    of a unit (`unitLabel`).
  - `ImagoCore.DisplayMapping`: window, gamma and a 256-entry colour table to 8-bit RGB in Double (the exact reference for a
    shader's Float32 arithmetic), masked grey for negative values.
  - `ImagoFFT.FFTRegion` (the square even region: drawn, moved, resized, typed, centred, valid), `SpectrumBin`,
    `RadialChartScale.decadeMarks`, `SpectrumShape.aspect` and `FFTUnits` (length, reciprocal and spectrum units shown in nm
    and nm⁻¹), on `LengthUnit.nanometres(per:)`.
  - `ImagoFFT.SpectrumDisplay`: v = log₁₀(|F|² / (W·H)²) per bin (NaN for the DC and for zero or non-finite power) and the
    default window (median by a 2048-bin histogram, white beyond 3 bins of the centre); the log matches NumPy's to the last
    bit of Float32 on the pinned cases.

### Migration
None: every addition is new API; existing 0.1.0 call sites compile unchanged. `AxisCalibration.init(scale:unit:origin:)` is unchanged; `offset` and `init(offset:scale:unit:)` are added beside it.

## [0.1.0](https://github.com/mac4DSTEM/ImagoKit/compare/0.0.2...0.1.0) (2026-10-15)

### Added
- `ImagoAlignment`, drift and stack alignment, on the Float32 and Float64 paths:
  - `PhaseCorrelation.register(reference:moving:upsampleFactor:normalization:precision:)`, scikit-image's
    `phase_cross_correlation` (no masks, no `disambiguate`): the shift to apply to the moving image, the error and the phase
    difference (`ImageRegistration`, `PixelShift`, `Normalization`).
  - `ImageShift.shift(_:by:order:mode:cval:precision:)`, SciPy's `ndimage.shift` with orders 0 and 1 and the modes
    `constant`, `nearest`, `wrap`, `reflect`, `mirror`, `grid-constant`, `grid-wrap` (`ShiftOrder`, `ShiftMode`);
    `ImageShift.fourierShift` and `fourierShiftWithResidual`, SciPy's `ndimage.fourier_shift` on the image's FFT.
  - `DriftSeries.estimate(_:reference:upsampleFactor:normalization:precision:)` against the first frame, the mean frame or the
    previous frame (cumulated) (`DriftReference`).
  - `AlignedSum.sum(_:shifts:method:precision:)`: the aligned sum and mean with the per-pixel overlap count
    (`AlignmentMethod`, `AlignedStack`).
  - `AlignmentError` with texts.
- DocC catalogues for `ImagoCore`, `ImagoFFT` and `ImagoFilters`; a README whose program is compiled and run by
  `tools/readme-consumer` in CI.

### Changed
- Nothing in 0.0.2's API.

### Fixed (before release)
- `ImageShift.shift` in `reflect` mode returned `cval` for a whole-number shift of 4n, 6n, … pixels on an axis of n pixels
  (a coordinate reduced to exactly 0 by the period was mapped outside); now the reflected pixel, as SciPy. Tested by the
  periodic-mode identity (a shift by whole periods returns the image) for `reflect`, `mirror` and `grid-wrap`.

### Removed
- `ImagoAlignmentScope`, the placeholder that named the module's registration.

### Known limits
- The shift and its error are compared with scikit-image on 330 cases: equal on every Float64 case; on Float32, a case
  whose two largest correlation samples lie within the Float32 noise of the correlation is held to the set of shifts that
  noise cannot tell apart (117 cases), not to equality.
- A first call of a vDSP 1D FFT or DFT size in a process can differ from later calls by one Float32 ulp (up to 7.9e-8 of the
  maximum, intermittent; also in the code ImagoCore's `FFT2D` came from). No result is promised bit-identical between two
  runs of a Float32 product.

- `DriftSeries.estimate` holds every frame's spectrum at once (a 20-frame 4096² stack needs about 2.7 GB on Float32, 5.4 GB
  on Float64); `.mean` gives shifts relative to the stack's average position, accurate to about 0.2 px on a drifting stack
  (scikit-image's own error there); the Float32 path returns shifts as `Double(Float)` (5.1 reads 5.0999999).

### Migration
Additive: no 0.0.2 code changes. Depend on the product `ImagoAlignment` to use the new module. Code that named
`ImagoAlignmentScope` deletes that line.

## [0.0.2](https://github.com/mac4DSTEM/ImagoKit/compare/0.0.1...0.0.2) (2026-10-15)

### Added
- `ImagoFFT.MaskedInverseFFT` (Bragg filtering: raised-cosine spots with their Friedel partners, the union by maximum,
  `imaginaryMax` reported) and `SpotMeasurement.maskSpot(radius:edge:)`.
- `ImagoFilters.HRTEMFilter`: the average background subtraction and Wiener filters (Kilaas 1998, as D. R. G. Mitchell's
  DigitalMicrograph script describes them), every stage in the result; never compared with DigitalMicrograph.

### Migration
Additive. `ImagoFiltersScope` (0.0.1's placeholder) is gone. For an application that carried the originals of these types, the
switch deletes them and converts its image type to `Micrograph`: `MaskedInverseFFT.compute` takes a `Micrograph` and
returns `SpectrumValues`; `HRTEMFilter.filter` returns a `Result` and `HRTEMFilter.outputs(_:like:)` gives the two images;
`FFTMask.spot`-style helpers become `SpotMeasurement.maskSpot`; error enums are `MaskedInverseFFTError` and
`HRTEMFilterError` (with `maskCount` for a wrong mask length). The Float32 path is the originals' arithmetic: the same
bits in steady state.
